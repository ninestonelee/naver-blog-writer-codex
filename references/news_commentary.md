# 기사·사건 해설 블로그

## 원문과 사실 확인

- 사용자가 준 기사 URL을 먼저 읽고 매체·기자·게시 날짜·사건 발생 시점을 확인한다. 과거 경험을 소개한 기사를 현재 발생한 사건으로 바꾸지 않는다.
- 검색 도구에서 본문을 읽지 못하면 브라우저의 공개 기사나 기사원문 링크를 확인한다. 다른 보도가 도움이 되면 교차 확인하되 같은 기사의 재전송을 독립 검증으로 세지 않는다. 접근 제한을 우회하지 않는다. 본문을 끝내 확인할 수 없다면 기사 텍스트를 요청한다.
- 인용된 방송·유튜브 원본을 직접 확인하지 않았으면 직접 확인한 것처럼 쓰지 않는다. 발언과 수치는 `해당 매체 보도에 따르면`처럼 귀속한다.
- 정확한 손실액·동기·실패 원인 등 보도만으로 알 수 없는 사실을 추정하여 단정하지 않는다.

## 독립적인 해설

- 사건의 핵심 사실만 간결하게 소개하고, 독자가 이해할 질문과 분석 중심으로 새 구조를 만든다. 원문의 제목·문단 순서·비유·특징적인 표현을 따라가며 단어만 바꾸지 않는다.
- 원문 전체를 대체할 만큼 상세하게 재구성하지 않는다. 직접 인용은 필요한 짧은 부분으로 제한하고 따옴표와 출처를 표시한다. 출처 표기 자체가 무단 전재를 허용하는 것은 아니다.
- 보도 사실과 일반적인 해석을 명확히 나눈다. 별도 해설의 배경 개념은 필요한 경우 공식·일차 자료로 확인해 출처를 붙인다.
- 이해를 위한 계산은 `가상 예시이며 당사자의 실제 수치가 아님`을 수치 바로 앞에 표시한다. 계산식과 전제를 확인한다.
- 기사 사진·캡처·인물 초상은 복사하지 않는다. 유명인 이슈는 실제 인물과 닮지 않은 가상 인물을 통해 기사 맥락을 표현하고, 소품만으로 대체하지 않는다. 구체적인 장면·외모·고지 기준은 [제작 절차](production_workflow.md)의 유명인 이미지 기준을 따른다.
- 저작권에 위배되지 않는다고 보장하거나 임의의 표절률·안전 비율을 제시하지 않는다. 원문을 확인한 범위, 인용·이미지 사용 범위를 정확하게 설명한다.

## 제목과 본문

- 개인 감상이 없어도 중립적인 해설로 진행한다. 가상의 운영자 경험을 만들지 않는다. 원고를 요청하면 내용에 맞는 제목으로 작성하고 전체 제작을 이어간다.
- 홈판용 제목을 따로 요청하면 후보 5개와 추천 1개를 제시한다. 확인된 숫자·궁금증을 사용하되 물음표만 붙여 입증되지 않은 원인·의혹을 암시하지 않는다. 제목의 약속은 본문에서 답한다.
- 사례: `재고가 약 500개 남았다는 과거 경험`은 보도에 귀속할 수 있지만, `응원이 구매로 이어지지 않아 실패했다`는 원인이 확인되지 않았다면 당사자의 사실처럼 제목에 넣지 않는다.
- 제목 후보만 요청한 경우에는 원고·이미지를 다시 만들지 않는다. 제목을 적용하면 원고 제목, HTML title과 h1, 두 HTML 및 ZIP을 동기화한다.

## 완성물

원고가 끝나면 [제작 절차](production_workflow.md)에 따라 이미지 순차 생성, 01부터 번호 지정, HTML 2종, 본문 끝 # 태그와 별도 쉼표 태그, 전체 ZIP을 완성한다. 명시적으로 범위를 제한한 요청은 그 제한을 따른다.
