# 글 작성 후 이미지·HTML 제작

이 문서는 새 블로그 콘텐츠의 전체 제작과 이미지·HTML 후속 요청에 사용한다. 제목·본문·이미지 프롬프트가 이미 있으면 대화의 최신 확정본을 이어받는다. 번호는 이미지 배치 순서이며 글 소제목 번호와 구분한다.

## 이미지 순차 생성

- 새 콘텐츠 전체 제작에는 이미지 생성이 포함된다. 프롬프트만 요청한 경우에는 생성하지 않는다. 이미지 제작 단계에서는 썸네일 1장 → 본문 소제목 순으로 한 장씩 생성한다. 보통 본문 5개 섹션이면 총 6장이다. 사용자가 정한 장수·스타일이 우선이다.
- 내장 `image_gen`을 사용하며, 사용 가능한 `imagegen` 스킬 지침을 따른다. 한 장 완료 후 다음 장을 호출한다. 도구 실패 시 실패 위치를 알리고 미완성 장만 처리한다. 유료 외부 API로 임의 전환하지 않는다.
- 프롬프트의 가로형 16:9, 글자 없음, 실존 인물의 외모·닮은꼴 재현 없음 조건을 유지한다. 시리즈의 빛·색감·질감을 통일한다. 업무 경험담에는 따뜻한 자연광과 네이비·크림을 기본 후보로 삼되 다른 주제나 사용자 지정 스타일에 강제하지 않는다.
- 각 결과를 확인하고 내용·글자·얼굴·구성을 점검한다. 성공한 이미지를 번호 변경이나 HTML 요청 때문에 재생성하지 않는다.

### 유명인 이슈의 가상 인물 이미지

- 유명인이 등장하는 기사에서는 실제 인물과 닮지 않은 가상 인물을 기본으로 사용하고, 기사의 핵심 상황·활동·감정을 장면에 반영한다. 유명인이라는 이유만으로 빈 장소나 소품만 반복하지 않는다. 가상 인물의 얼굴은 보여도 된다. 사용자가 인물 없는 이미지를 요청하면 그 선택을 따른다.
- 직업·활동·공간·행동처럼 이슈를 이해하는 데 필요한 맥락은 유지하되, 얼굴·헤어스타일·체형·고유 표식의 조합으로 당사자를 알아보게 만들지 않는다. 기사 사진이나 실제 인물 사진을 외모 참조로 사용하지 않는다.
- 각 이미지가 해당 소제목의 내용을 전달하도록 구체적인 행동·표정·장소·소품을 정한다. 예: 테니스 선수의 수술 후 복귀 기사 → 가상의 성인 여성 선수가 코트에서 자신감 있게 경기 준비를 하는 장면. 의료·신체 이슈에서도 신체 일부의 과장, 임의의 전후 비교, 확인되지 않은 결과를 그리지 않는다.
- 프롬프트에 `entirely fictional person, no resemblance to any real person or celebrity, conceptual editorial scene, not a documentary image`를 포함하고 가상 인물의 외모와 상황을 구체적으로 기술한다. 여러 장에서 같은 인물이 이어지면 가상 인물의 외형과 전체 화풍을 유지한다. 수채화·실사풍 등은 사용자 지정과 현재 글의 스타일을 따르며 이번 사례의 화풍을 영구 고정하지 않는다.
- 이미지 아래에 `AI 생성 이미지 · 기사 속 실제 인물과 무관한 가상의 인물입니다.`를 표시한다. HTML 2종에도 같은 설명을 유지하고, 실제 현장·인물의 기록으로 소개하지 않는다.
- 결과를 검토할 때 실존 인물의 재현 여부, 이슈·소제목과의 관련성, 가상 인물 표시를 확인한다. 가상 인물을 썼다는 이유만으로 법적 무침해를 보장하지 않는다.

## 파일 번호와 전달

썸네일부터 1로 시작하는 두 자리 번호를 사용한다. 예:

```text
01-thumbnail.png
02-completion-gap.png
03-check-results.png
04-set-criteria.png
05-review-role.png
06-finished-review.png
```

- 확장자는 실제 생성 형식을 따른다. 본문 파일명은 해당 글의 섹션을 설명하는 영문 슬러그로 정한다.
- 사용자 지정 저장 위치를 우선한다. 프로젝트의 생성물 저장 규칙이 있으면 따르고, 없으면 `output/blog/<slug>/`에 글·이미지·프롬프트를 모은다. 개인 경로나 예시 주제를 다른 프로젝트에 하드코딩하지 않는다.
- 기본 생성 위치의 원본은 보존하고 작업 폴더로 복사한다. 파일 충돌 시 기존 결과를 덮어쓰지 말고 버전 폴더를 사용한다.
- 이름만 변경하면 이미지 바이트를 유지한다. HTML 자리표시자·이미지 경로·프롬프트 문서·ZIP 내부 파일명도 함께 갱신한다. 이미 요청한 번호 형식이면 그대로 확인한다.
- 최종 이미지 ZIP을 생성하고, 파일 수·순서·원본 일치를 확인한다. 프롬프트 모음은 실제 사용한 최종 프롬프트와 대응 파일명을 기록한다. 생성 도구와 파일·ZIP 링크를 간단히 전달한다.

## 읽기 편한 HTML

- 기존 모드·선택 제목·본문 내용을 보존한다. HTML 요청 때문에 제목 선정이나 검색형 글쓰기를 다시 시작하지 않는다. 디자인을 위해 사실·경험·통계·분량을 추가하지 않는다.
- 독립적으로 열리는 UTF-8 HTML 파일을 만든다. `lang="ko"`, viewport, 제목, 본문 구조를 제공하고 외부 폰트·스크립트 없이 읽히게 한다.
- 모바일 본문은 17~19px, 줄간격 1.8~2.0, 좌우 여백 20~24px를 기본으로 한다. 데스크톱은 본문 최대 폭 700~760px 정도로 제한한다. 한국어 단어 단위 줄바꿈과 긴 파일명 줄바꿈을 지원한다.
- 차분한 단색 배경, 명확한 제목 계층, 넉넉한 문단 여백을 사용한다. 핵심 문장만 강조하고 인용 박스와 체크리스트는 글 흐름에 필요한 위치에 둔다. 장식이나 중첩 카드로 본문을 압도하지 않는다.
- 핵심 본문 서식에는 인라인 CSS를 사용한다. 반응형 보완은 문서 스타일로 처리할 수 있으나 네이버 편집기에서 동일하게 유지된다고 보장하지 않는다. 본문 중간에 제작 설명·프롬프트·태그를 섞지 않는다. 본문 마지막에는 별도의 해시태그 영역을 둔다.

### 완성본과 편집용 HTML

- 전체 제작은 이미지가 실제 표시되는 완성 HTML과 이미지 자리·파일명을 표시한 편집용 HTML 두 가지를 제공한다. 특정 버전만 요청했으면 그 버전만 제공한다.
- 완성본은 HTML만 이동해도 보이도록 이미지 내장을 우선 고려한다. 상대 경로를 쓰면 해당 이미지 파일을 같은 ZIP에 포함한다. 네이버 업로드는 별도이며 자동으로 이뤄졌다고 말하지 않는다.
- 기사 해설 이미지에는 `AI 생성 해설용 이미지`라고 표시한다. 인물·사업장과 혼동될 장면에는 실제 당사자의 사업장이나 상품을 촬영한 사진이 아니라는 설명을 붙인다. 기사 사진·영상 캡처를 재사용하지 않는다.

### 이미지 위치 표시

사용자가 삽입 자리를 요청하면 이미지 태그를 깨진 경로로 넣는 대신 눈에 보이는 자리표시자를 만든다.

- 제목·도입부 부근에 썸네일 자리, 각 관련 섹션에 본문 이미지 자리를 둔다.
- 각 자리에 `이미지 01 · 썸네일`처럼 번호·용도, 장면 설명, 정확한 파일명을 표시한다. 예: `01-thumbnail.png`.
- 기존 이미지가 있으면 파일명을 그대로 사용한다. 아직 생성하지 않았다면 예정 파일명임을 표시하고 이미지가 존재한다고 말하지 않는다.
- 실제 이미지를 넣어 달라는 요청에는 저장된 이미지를 연결한다. 자리 표시만 요청한 것을 실제 이미지 삽입이나 재생성으로 바꾸지 않는다.

### 본문 끝 해시태그

- 두 HTML 모두 마지막 문단·FAQ·출처 뒤, article 내부 맨 마지막에 해시태그 8개를 넣는다. 형식은 `#권은비 #정예인 #의류사업`처럼 공백 구분이며, 모바일에서는 자연스럽게 줄바꿈한다. 태그 내용은 해당 글에서 선정한 목록을 사용한다.
- 작은 글자와 차분한 단색 배경으로 본문과 구분하되 읽기 쉬운 대비를 유지한다.
- 후속 태그 수정은 기존 영역을 갱신한다. 영역을 중복 추가하지 않는다. 별도 `tags.txt`는 `#` 없이 쉼표와 공백으로 구분한다.

### 검증과 전달

- 가능한 경우 로컬 브라우저에서 모바일 약 390px 및 데스크톱 약 1280px로 확인한다. 가로 넘침, 제목·본문 줄바꿈, 이미지 자리 수·파일명 대응을 점검한다. 이미지가 연결된 문서는 로딩도 확인한다.
- 확인한 범위만 보고한다. 로컬 HTML 확인을 실제 네이버 편집기 검증이라고 부르지 않는다. 붙여넣기 절차는 [편집기 안내](editor_paste_guide.md)를 참고한다.
- 전체 ZIP에는 원고, 번호 이미지, HTML 2종, tags.txt, 실제 프롬프트를 포함한다. 수정 후 ZIP도 갱신하고 압축 내부 HTML이 최신 파일과 일치하는지 확인한다.
- 두 HTML의 출처, 가상 수치 안내, 이미지 설명, 본문 끝 # 태그가 유지되는지 확인한다.
- 완성 HTML·편집용 HTML·전체 ZIP 링크를 전달하고 가능하면 앱에서 미리보기를 연다. 네이버로 옮길 때 자리표시자를 해당 이미지로 교체하고 서식을 확인하도록 짧게 안내한다. 자동 발행은 이 제작 요청에 포함되지 않는다.

## 태그 후속 요청

별도 태그 응답과 tags.txt의 기본은 `#` 없이 쉼표와 공백으로 나눈 한 줄이다. HTML 본문 끝의 `#` 포함 해시태그 영역과 구분한다. 태그만 요청하면 인사·설명·제목·코드블록 없이 태그만 반환한다. 이미 선정한 태그를 유지하고 형식만 바꾼다.

```text
AI업무자동화, 업무자동화, AI활용, 생성형AI, 업무생산성, 직장인AI, 자동화경험, 결과검증
```

## 생성 도구가 없는 환경

내장 이미지 도구가 제공되지 않으면 이미지 생성 완료로 표시하지 않는다. 원고·이미지 프롬프트·예정 파일명을 표시한 HTML을 준비하고, 실제 이미지가 미생성임을 알린다. 이미지 포함 완성본은 생성 도구를 사용할 수 있을 때 이어간다. 없는 도구를 설치된 것으로 가정하거나 외부 유료 API로 임의 전환하지 않는다.
